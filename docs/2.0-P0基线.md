# InnerNet 2.0 P0 基线

## 目录与边界

`innerNet-2.0.0` 是独立维护目录，来源为 InnerNet 1.0 的稳定源码基线。历史 `inner-net`、`inner-net-mac` 和 1.0 统一目录不作为 2.0 的修改来源。

P0 不实现设备发现、安全配对、原生 P2P 或 WOL。本轮只冻结现状并确认回归基线。

## 当前职责边界

- `electron/main.js`：Electron 主进程编排和 IPC；Windows 高权限能力由平台守卫控制。
- `electron/windows-share-acl.js`、`electron/ssh.js`：Windows 共享/ACL/SSH 平台边界。
- `electron/smb-mount.js`：macOS SMB 挂载、autofs 和 LaunchAgent 相关逻辑。
- `electron/chat-server.js`、`electron/chat-protocol.js`、`electron/chat-storage.js`：群聊协议、消息持久化和缓存管理。
- `src/App.jsx`、`src/components/`、`src/styles.css`：公共 React 界面；平台差异通过能力和现有平台属性进入。

## 已知缺口

- 尚未有 Device Schema、稳定 deviceId 和能力解析器。
- 尚未有跨设备发现、身份配对、P2P 传输或 WOL。
- 现有首页仍是 1.0 的功能页面，不是设备中心。
- 真实 Windows、macOS 双机和 WOL 硬件验证不在本轮环境内完成。

## P1/P2 当前进度

P1 已完成：Device Schema、稳定 `deviceId`、本机身份持久化、能力解析器和 `device:info` IPC。

P2 已完成：设备注册表合并、IP 变化、离线超时、身份冲突检测、只读设备中心，以及基于 Node 原生 UDP 的最小字段发现服务（49321 端口）。发现公告不包含身份指纹、IP、主机名、令牌、私钥或可用状态；接收方仅通过来源地址补充临时地址。配对前仍不开放任何敏感操作。

P3 已完成安全基础：一次性六位配对码、5 分钟有效期、最多 5 次尝试、成功/拒绝/过期状态、可信指纹绑定与解除信任，以及 Electron 本地配对 IPC 和设备中心配对入口。跨设备配对消息转发、CredentialStore 和真实双机握手尚未完成，P3 Gate 仍待补齐。

## P1 最小实施清单

1. 新增 `core/device-schema`：schemaVersion、校验、默认值、迁移和序列化。
2. 新增 `core/device-identity`：持久化 deviceId 和公开设备资料。
3. 新增 `core/capability-resolver`：统一计算 supported/configured/available/verified/reasonCode。
4. 为 Schema、迁移、deviceId 稳定性和 Windows/macOS 能力差异补充纯函数测试。
5. 仅将旧能力映射到新模型，保持现有 SMB、SSH、挂载和群聊调用路径不变。
