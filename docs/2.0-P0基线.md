# InnerNet 2.0 P0 基线

## 目录与边界

`innerNet-2.0.0` 是独立维护目录，来源为 InnerNet 1.0 的稳定源码基线。历史 `inner-net`、`inner-net-mac` 和 1.0 统一目录不作为 2.0 的修改来源。

> P0 基线范围（历史）：P0 阶段不实现设备发现、安全配对、原生 P2P 或 WOL，只冻结现状并确认回归基线。这些能力已在后续 P2-P5 完成，见下方「P1-P5 完成进度」与 [版本更迭.md](版本更迭.md)。

P0 不实现设备发现、安全配对、原生 P2P 或 WOL。本轮只冻结现状并确认回归基线。

## 当前职责边界

- `electron/main.js`：Electron 主进程编排和 IPC；Windows 高权限能力由平台守卫控制。
- `electron/windows-share-acl.js`：Windows 共享/ACL 平台边界。
- `electron/smb-mount.js`：macOS SMB 挂载、autofs 和 LaunchAgent 相关逻辑。
- `electron/chat-server.js`、`electron/chat-protocol.js`、`electron/chat-storage.js`：群聊协议、消息持久化和缓存管理。
- `src/App.jsx`、`src/components/`、`src/styles.css`：公共 React 界面；平台差异通过能力和现有平台属性进入。

## P1-P5 完成进度（截至 2026-08-30，当前实际）

P1 已完成：Device Schema、稳定 `deviceId`、本机身份持久化、能力解析器和 `device:info` IPC。

P2 已完成：设备注册表合并、IP 变化、离线超时、身份冲突检测、只读设备中心，以及基于 Node 原生 UDP 的最小字段发现服务（49321 端口，定向子网广播）。发现公告仅含最小公开信息；配对前不开放敏感操作。

P3 已完成：一次性六位配对码、5 分钟有效期、最多 5 次尝试、成功/拒绝/过期状态、可信指纹绑定与解除信任、Electron 本地配对 IPC 与设备中心配对入口；跨设备配对消息转发、CredentialStore、`identityPublicKey` 互留存与**真实双机握手均已验收**，解除配对撤销凭据（revocation）双向同步。P3 Gate 已补齐。

P4 已完成完整链路重构：版本化 transfer manifest、transferId 绑定授权、SHA-256 校验、乱序分块接收、原生流式发送；服务端生成并绑定配对会话的 Ed25519 传输挑战签名接口与 `transfer:requestChallenge` IPC 已接入；**P2P 传输 UI/IPC 已接通完整链路**（`TransferPage.jsx` 三块布局：我要发送/我要接收/设置；`transfer:offer/sends/listOffers/decide/status/selectFile` IPC；文件夹自动 zip 打包；挑战按配对留存公钥签发与校验；token 鉴权分块与状态）。双机真机端到端大文件验证与真实吞吐测试仍属 P6 联调。

P5 已完成：局域网设备「访问过本机的设备」只读记录（`core/access-log.js`，记录 requesterId+IP+来源+时间，取代原 ARP 扫描方案）、远程唤醒（WOL）魔术包与上线探测、WOL 状态机与配置持久化。真实硬件关机唤醒需用户在有 WOL 支持的设备上验证一次。

## 2026-08-30 批量重构 8 项（当前实际）

详见 [版本更迭.md](版本更迭.md)「批量功能修正与重构（8 项）」。要点：

1. **同步停止生效 + 对端通知**：引入 6 位 pairKey 配对码（主端自动生成、从端表单填写），修复两端任务 id 各自独立导致 404 的根因；`runCycle` 循环检查 `enabled` 支持中途取消。
2. **同步编辑弹窗排版**：任务表单 grid 对齐。
3. **忽略规则可视化**：主端任务可「从目录选择」勾选自动生成 ignore 规则。
4. **设备中心**：移除 ARP 扫描展示；改为「访问过本机的设备」（`core/access-log.js`，群聊发言/共享清单拉取/文件同步请求时记录 requesterId+IP+来源）。
5. **群聊实名**：`/api/msg` 必带 `requesterId`（本机 deviceId），匿名 400；前端自动附带设备名。
6. **聚合挂载全自动**：macOS 每 60 秒检查已配对设备的新共享并自动挂载（需主机统一密码）。
7. **P2P 传输重构**：接通完整链路（此前 authorize 未接线导致 offer/分块全部 403）；挑战按配对留存公钥签发与校验；token 鉴权分块/状态；新增 transfer:offer/sends/listOffers/decide/status；界面重构为三块布局，文件夹自动打包 zip，无文件大小限制。
8. **服务设置重构**：补齐文件同步（7892）端口，按当前服务列表分组展示。

测试 123/123、ESLint 0 error、build 通过。
