# P2 双机发现联调记录

> 本记录为 P2 阶段历史联调（2026-08-27）。文中「P2P、配对确认和 WOL 尚未完成，仍按 P3/P4/P5 推进」为当时状态；截至 2026-08-30，P3/P4/P5 均已实现，见 [版本更迭.md](版本更迭.md)。

## 1. 联调环境

- Windows：`192.168.5.50`
- macOS：`192.168.5.51`
- Node.js：`v24.19.0`
- Electron：`44.0.0`
- 发现端口：UDP `49321`
- 群聊服务端口：TCP `7890`

两端均运行 `innerNet-2.0.0` 最新代码。

## 2. 初始问题

Windows 端设备中心可以看到 Mac，Mac 端看不到 Windows。Windows 端检查结果：

```text
0.0.0.0:7890 LISTEN
192.168.5.50:7890 ↔ 192.168.5.51 已建立连接
0.0.0.0:49321 UDP 已监听
```

因此 TCP 群聊和 Windows 监听服务正常，问题集中在 UDP 发现包的单向到达。

## 3. 排查思路

1. 先确认 Windows TCP `7890`，排除 IP、网络隔离和聊天服务未启动。
2. 再确认 Windows UDP `49321` 正在监听，排除发现服务未启动。
3. 检查 Windows 网络配置，发现网络类别为 `Public`。公共网络配置会采用更严格的入站规则，即使程序监听了端口，也可能丢弃 UDP 入站包。
4. Mac 防火墙已关闭，且 Windows 能看到 Mac，说明 Mac → Windows 方向可以工作。
5. 为 Windows 增加仅针对 UDP `49321` 的入站规则，避免放宽整个公共网络配置。
6. 防火墙规则仍不能解决时，继续检查广播地址。原实现只向 `255.255.255.255` 发送，部分网卡/交换设备会过滤该全局广播。

## 4. Windows 防火墙处理

在管理员 PowerShell 中执行：

```powershell
New-NetFirewallRule `
  -DisplayName "InnerNet Discovery 49321" `
  -Direction Inbound `
  -Protocol UDP `
  -LocalPort 49321 `
  -Action Allow `
  -Profile Public
```

验证规则：

```powershell
Get-NetFirewallRule -DisplayName "InnerNet Discovery 49321"
Get-NetUDPEndpoint -LocalPort 49321
```

## 5. 代码改动

### 5.1 定向子网广播

文件：`electron/discovery-service.js`

发现服务现在同时发送：

- `255.255.255.255`
- 根据本机 IPv4 网卡推导的定向广播，例如 `192.168.5.255`

这样可以绕过部分网络设备对全局广播的过滤。

### 5.2 网卡地址注入

文件：`electron/main.js`

设备发现启动时将 `getLocalIPs()` 返回的 IPv4 地址传给发现服务，用于计算定向广播地址。

### 5.3 已存在身份资料的网络更新

文件：`core/device-identity.js`

设备身份文件保留稳定 `deviceId`，但允许在每次读取时更新网络地址等可变资料，避免首次创建 `device.json` 后一直使用空地址。

### 5.4 最小公开发现字段

发现公告只包含设备中心所需的公开信息：

- `deviceId`
- 设备名称和类型
- 平台与应用协议版本
- 服务端口
- 能力的 `supported/configured` 摘要

不包含：

- 私钥
- 长期令牌
- 配对码
- 完整身份指纹
- 用户目录和聊天数据

## 6. 最终验证结果

更新 Windows 和 macOS 两端代码并重启后：

- Windows 设备中心可以看到 Mac
- Mac 设备中心可以看到 Windows
- 双向设备发现恢复正常
- TCP `7890` 群聊连接保持正常
- P2P、配对确认和 WOL 尚未因本次联调自动完成，仍按 P3/P4/P5 阶段推进

## 7. 后续注意事项

- 两端必须运行同一份 `innerNet-2.0.0` 最新代码；旧 1.0 程序不包含定向广播逻辑。
- Windows 公共网络环境建议只开放 UDP `49321`，不要直接关闭整个防火墙。
- 设备发现只代表“发现”，不代表“信任”；敏感操作必须等待 P3 配对完成。
- 如果更换网段，需要重新确认定向广播地址和 Windows 防火墙规则。
