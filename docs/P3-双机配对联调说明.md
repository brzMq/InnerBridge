# P3 双机配对联调说明

## 实现边界

设备发现与配对分离：UDP `49321` 仅发布最小设备资料；TCP `7891` 是专用配对服务，仅提供以下接口：

- `POST /api/pair/request`：发起方提交双方 deviceId，接收方产生会话并通知桌面界面。
- `GET /api/pair/status/:sessionId`：发起方轮询配对状态。
- `POST /api/pair/confirm`：接收方通过本机 Electron IPC 确认验证码。

macOS 不会为了配对而开放 Windows 的完整群聊、聊天历史或附件上传服务。配对码只在发起端显示，不会作为网络通知内容发送给接收端。

## 双机验证

1. 将同一版源码同步至 Windows 与 macOS，并分别重启 `npm run dev`。
2. 确认设备中心已双向发现。
3. 在设备 A 的设备中心，对设备 B 点击“发起配对”；A 应显示 6 位验证码。
4. B 应立即显示“请求与本机配对”的卡片；在 B 输入 A 显示的验证码并点“确认配对”。
5. A 最多约 2 秒显示“对端已确认验证码，配对完成”。

Windows 网络类别为 Public 时，在管理员 PowerShell 添加专用入站规则：

```powershell
New-NetFirewallRule `
  -DisplayName "InnerBridge Pairing 7891" `
  -Direction Inbound `
  -Protocol TCP `
  -LocalPort 7891 `
  -Action Allow `
  -Profile Public
```

不要开放整个端口范围，也不要把 TCP `7891` 误用为群聊端口；群聊仍使用 Windows 端 TCP `7890`。
