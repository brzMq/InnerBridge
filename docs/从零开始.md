# 从零开始使用

## 1. 准备环境

两端都安装 Node.js v24.19.0，然后把**同一个项目目录**分别复制到 Windows 和 Mac。项目支持范围为 `>=24.19.0 <25`，Electron 固定在 44.x。不要复制 `node_modules`、`dist`、`release`；每台机器独立执行 `npm install`。

## 2. Windows 共享端

1. 在项目目录打开管理员 PowerShell，运行 `npm install`、`npm run electron:ensure`、`npm run dev`；开发服务使用 6300 端口。也可双击 `启动 InnerNet.bat`，脚本会申请管理员权限并自动补齐 Electron 二进制。
2. 在“共享文件夹”页添加目录。统一账号模式使用当前 Windows 登录账号和密码。共享卡片的密码默认以 `••••••••` 遮罩展示，眼睛按钮可临时查看，「复制连接信息」复制真实密码。
3. 程序会把裸账号规范成 `机器名\用户名`，用 `Get-SmbShareAccess` 验证 Full/Allow。若补授权失败，会保留目录和描述、重建共享对象并复验，不删除文件。
4. 无需额外配置：共享清单接口随群聊服务一起监听 `7890` 端口，程序启动即可用。
5. 首次与 Mac 配对时，在“设备中心”出现的请求里输入 Mac 端显示的六位配对码并允许。

## 3. macOS 挂载端

1. 在项目目录运行 `npm install`、`npm run electron:ensure`、`npm run dev`；也可双击 `启动 InnerNet.command`。
2. 先在"设备中心"找到 Windows 设备点「发起配对」，双方配对码一致后由 Windows 端确认。
3. 回到"聚合挂载"页填写 Windows IP，点「拉取共享清单」；只同步共享名和账号，SMB 密码需要在本机填一次，之后会保留复用。
4. **主机统一密码**：进入「聚合挂载」页的「主机账号」维护区，对出现过的主机「设置/更新」SMB 统一密码，N 个共享只填一次；之后同步来的新共享即使密码为空也能挂载（自动用主机密码）。Windows 端改了共享密码，在这里更新即可。
5. 手动模式立即挂载；重复点击是幂等操作，会提示已经挂载。卸载后只清理空挂载目录。
6. 自动模式安装当前用户的 LaunchAgent，登录启动并每 30 秒检查一次；网络恢复后自动重挂，不修改 `/etc/auto_master`，不需要关闭 SIP。
7. **新共享自动挂载**：macOS 每 60 秒检查已配对在线设备的新共享并自动挂载（需主机统一密码），全程写入运行日志；界面顶部有说明提示。

## 4. 常见检查

- 网络：Mac 到 Windows 的 TCP `445`（SMB 挂载）与 `7890`（共享清单）必须可达。
- 清单同步：拉取失败先看两端是否已完成配对，再看 Windows 端群聊服务是否在运行。
- Windows ACL：`Get-SmbShareAccess -Name "共享名"` 应看到 `机器名\用户名`、Full、Allow，不能是 `机器名\` 空用户名。
- Mac 认证：程序使用 RFC 3986 编码后的 SMB URL；`mount_smbfs -N` 不读取钥匙串，统一版不再依赖该错误假设。
- 调试：源码改变后重启 `npm run dev`；仅发布时运行平台打包命令。

## 5. 从旧双目录迁移

- 不要把旧目录中的 `electron/main.js`、平台组件或 `package-lock.json` 覆盖到统一版。
- 不要复制 `node_modules`、`dist`、`release`、`.workbuddy`、`.DS_Store`。
- 应用名称和用户数据目录保持不变，因此在同一台电脑上启动统一版时，原有共享清单、挂载清单和设置会继续使用。
- 若要进行完全全新的环境测试，应先退出应用并**备份后重命名**用户数据目录，不要直接删除：
  - Windows：`%APPDATA%\InnerNet 内网共享\`
  - macOS：`~/Library/Application Support/InnerNet 内网共享/`
- Windows 的 SMB 共享和本地账号属于系统状态，不在源码目录内。清空用户数据前应先记录或卸载现有共享，避免重新创建时名称冲突。

## 6. 新增能力（文件同步 / P2P 传输 / 访问记录 / 远程唤醒）

### 文件同步（多任务、单向主从、配对码）

1. 两端都完成配对并在「文件同步」页签进入配置。
2. 主端：选「主端」角色、选目录、选从端设备（自动带出地址）；任务创建后自动生成 6 位**配对码**（pairKey），并通过已配对身份向从端发送签名邀请。
3. 从端：收到邀请后应用自动切到「文件同步」并弹出新建从端任务窗口。任务名、角色、配对码、主端设备、地址和端口已自动填写，只需选择从端目录、创建任务并点「启动」。邀请未送达时仍可按原方式手工填写配对码。
4. 主端实时监听目录变更并推送到从端；主端删除的文件在从端进入 `.innernet-trash/`（默认 7 天，可恢复/清空）。
5. 运行中的任务锁定配置（🔒），先停止再编辑；任一端停止都会即时通知另一端并弹出需要手动关闭的提示框。
6. 推送失败的文件下一轮自动重推（任务卡片显示「待补偿 N 个文件」）。
7. 主端可配 gitignore 风格忽略规则，可「从目录选择」勾选自动生成。
8. 同步走配对 Ed25519 验签，未配对设备无法推送或拉取；端口 `7892`，已纳入服务健康检查。
9. macOS 从端目录勿落在 SMB 挂载卷上（`fs.watch` 网络卷不可靠）。

### P2P 传输（P4，已重构完整链路）

1. 两端都完成配对后，在「P2P传输」页签操作。
2. **我要发送**：选文件或文件夹（文件夹自动打包为 ZIP）→ 选已配对接收设备 → 发送；进度卡片显示状态。
3. **我要接收**：对端发起的传输提议出现在这里，可接受或拒绝；接收目录在本机选择，远端不能指定。
4. 挑战按配对留存公钥签发与校验；token 鉴权分块与状态接口；无文件大小限制（流式分块）。

### 访问过本机的设备（只读记录）

设备中心「访问过本机的设备」区只读记录访问过本机服务的设备（拉取共享清单、群聊发言、文件同步请求时记录 requesterId+IP+来源+时间），不主动扫描、不对任何设备发包，仅显示与本机产生过实际交互的设备。

### 远程唤醒（WOL）

1. 在已配对设备的设备卡片点「设置远程唤醒」，填目标 MAC 与广播地址（可从本机网卡 MAC 复制给对方配置）。
2. 设备离线且已配置时显示「唤醒设备」；点击发送魔术包（UDP 广播，每地址 3 次）并轮询上线（最长 30 秒）。
3. 唤醒成功自动标记「已验证可唤醒」；未验证会明确提示「尚未实际验证」。唤醒失败按提示检查电源/BIOS/有线网络。
4. 目标配置按 `deviceId` 存本机 `wol-targets.json`，不进发现广播。
5. 「已配置」不等于目标网卡已允许唤醒。Windows 端还需在 BIOS/UEFI、网卡电源管理和 `Wake on Magic Packet` 高级属性中开启 WOL；睡眠后若网口灯熄灭，应先解决网卡待机供电问题。完整检查方法见[《系统使用说明》的“WOL 实机验证与故障排查”](系统使用说明.md#wol-实机验证与故障排查)。
