# 从零开始使用

## 1. 准备环境

两端都安装 Node.js v24.19.0，然后把**同一个项目目录**分别复制到 Windows 和 Mac。项目支持范围为 `>=24.19.0 <25`，Electron 固定在 44.x。不要复制 `node_modules`、`dist`、`release`；每台机器独立执行 `npm install`。

## 2. Windows 共享端

1. 在项目目录打开管理员 PowerShell，运行 `npm install`、`npm run electron:ensure`、`npm run dev`；开发服务使用 6300 端口。也可双击 `启动 InnerNet.bat`，脚本会申请管理员权限并自动补齐 Electron 二进制。
2. 在“共享文件夹”页添加目录。统一账号模式使用当前 Windows 登录账号和密码。
3. 程序会把裸账号规范成 `机器名\用户名`，用 `Get-SmbShareAccess` 验证 Full/Allow。若补授权失败，会保留目录和描述、重建共享对象并复验，不删除文件。
4. 无需额外配置：共享清单接口随群聊服务一起监听 `7890` 端口，程序启动即可用。
5. 首次与 Mac 配对时，在“设备中心”出现的请求里输入 Mac 端显示的六位配对码并允许。

## 3. macOS 挂载端

1. 在项目目录运行 `npm install`、`npm run electron:ensure`、`npm run dev`；也可双击 `启动 InnerNet.command`。
2. 先在“设备中心”找到 Windows 设备点「发起配对」，双方配对码一致后由 Windows 端确认。
3. 回到“聚合挂载”页填写 Windows IP，点「拉取共享清单」；只同步共享名和账号，SMB 密码需要在本机填一次，之后会保留复用。
4. 手动模式立即挂载；重复点击是幂等操作，会提示已经挂载。卸载后只清理空挂载目录。
5. 自动模式安装当前用户的 LaunchAgent，登录启动并每 30 秒检查一次；网络恢复后自动重挂，不修改 `/etc/auto_master`，不需要关闭 SIP。

## 4. 常见检查

- 网络：Mac 到 Windows 的 TCP `445`（SMB 挂载）与 `7890`（共享清单）必须可达。
- 清单同步：拉取失败先看两端是否已完成配对，再看 Windows 端群聊服务是否在运行。
- Windows ACL：`Get-SmbShareAccess -Name "共享名"` 应看到 `机器名\用户名`、Full、Allow，不能是 `机器名\` 空用户名。
- Mac 认证：程序使用 RFC 3986 编码后的 SMB URL；`mount_smbfs -N` 不读取钥匙串，统一版不再依赖该错误假设。
- 调试：源码改变后重启 `npm run dev`；仅发布时运行平台打包命令。

## 5. 从旧双目录迁移

- 不要把旧目录中的 `electron/main.js`、平台组件或 `package-lock.json` 覆盖到统一版。
- 不要复制 `node_modules`、`dist`、`release`、`.workbuddy`、`.DS_Store`。
- 应用名称和用户数据目录保持不变，因此在同一台电脑上启动统一版时，原有共享清单、挂载清单和设置会继续使用。
- 若要进行完全全新的环境测试，应先退出应用并**备份后重命名**用户数据目录，不要直接删除：
  - Windows：`%APPDATA%\InnerNet 内网共享\`
  - macOS：`~/Library/Application Support/InnerNet 内网共享/`
- Windows 的 SMB 共享和本地账号属于系统状态，不在源码目录内。清空用户数据前应先记录或卸载现有共享，避免重新创建时名称冲突。
