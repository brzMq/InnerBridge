# 统一源码架构

## 目标

一个仓库、一份依赖锁、一套前端和主进程，根据运行平台启用对应能力。仓库不包含 `node_modules`、构建产物或用户运行数据。

## 目录

主进程与渲染进程按职责分层，纯逻辑下沉到 `core/`，平台系统调用留在 `electron/` 的 `IS_WIN` / `IS_MAC` 分支。

### 设备与发现

- `core/device-schema.js` / `core/device-identity.js` / `core/capability-resolver.js` / `core/discovery.js`：设备 Schema、稳定 `deviceId`、能力解析器与发现协议。
- `electron/discovery-service.js`：UDP `49321` 设备发现，向 `255.255.255.255` 与定向子网广播同时发送；仅携带最小公开信息。

### 安全配对（P3）

- `electron/pairing.js`：专用配对服务（TCP `7891`），`request/status/confirm` 协议与六位一次性配对码。
- `electron/pairing-coordinator.js` / `electron/pairing-relay.js` / `electron/pairing-protocol.js`：配对协调、跨设备转发与协议。
- `core/light-auth.js`：Ed25519 挑战签发与签名验证，共享清单同步、P2P 传输和文件夹同步共用。
- `core/credential-store.js`：配对凭据与主机 SMB 密码（同套加密，存 `credentials.json` / `hostCredentials.json`）。
- `core/revocation.js`：解除配对撤销凭据签发/验签（由解除方用本机私钥签名，对端验签通过即解除）。

### 共享与挂载

- `electron/windows-share-acl.js`：Windows principal 规范化和共享 ACL 结果判断，保持纯函数便于跨平台测试。
- `electron/smb-mount.js`：SMB URL、挂载状态、LaunchAgent 文件生成，保持纯函数便于在 Windows CI 测试。
- `electron/main.js`：唯一 Electron 主进程；用 `IS_WIN` / `IS_MAC` 守卫系统调用，注册 host/sync/lan/wol 等 IPC。

### 群聊

- `electron/chat-protocol.js`：群聊历史边界、幂等键、回复快照和搜索选择器等纯协议逻辑。
- `electron/chat-storage.js`：聊天记录/附件统计与安全清理；仅由 Windows 本机 IPC 调用。
- `electron/chat-server.js`：HTTP/SSE 传输、持久化和附件服务，不承载页面状态；同时承载共享清单的
  `/api/shares/challenge` 与 `/api/shares/manifest`，由主进程注入签发器/校验器后才启用。

### 原生传输（P4，已重构完整链路）

- `core/transfer.js`：版本化 transfer manifest、transferId 绑定授权与 SHA-256 校验；`createTransferAuthorization` / `encodeTransferToken` / `decodeTransferToken`。
- `electron/transfer-server.js` / `electron/transfer-client.js`：局域网服务端乱序分块接收与原生流式发送；挑战按配对留存公钥签发与校验，offer token（Bearer）鉴权 chunk/status。
- **IPC 已接通**：`transfer:offer / sends / listOffers / decide / status / selectFile / info`。
- **UI 三块布局**（`src/components/TransferPage.jsx`）：「我要发送」（选文件/文件夹→选接收设备→发送进度）/「我要接收」（待接收列表→接受/拒绝→状态）/「设置」（端口与对端配置）。
- 文件夹默认使用无压缩 tar 容器保持目录结构，接收端完成路径检查和 SHA-256 校验后自动还原；设置中可切换为 ZIP。接收目录选择保留在本机 Electron IPC 边界。
- 发送历史持久化，默认显示最近五条；缓存目录和压缩策略通过设置持久化。发布后仍需在目标网络完成大文件吞吐和断网场景验收。

### 文件夹同步（多任务、单向主从）

- `core/sync-engine.js`：纯函数——扫描、差异计算、回收区路径、过期清理、退避、`carryFailures` 失败补偿、`buildIgnoreMatcher` 忽略规则匹配。
- `electron/sync-server.js`：从端 HTTP 端点 `challenge/list/begin/chunk/commit/trash/purge/notify`，按 `taskId`/`pairKey` 路由任务，`safeTarget` 防止 `../` 穿越；404 任务不存在 / 409 已停止。
- `electron/sync-service.js`：主端编排——多任务并存（每任务独立 watcher/防抖/全量轮/索引 `sync-index/<taskId>.json`）；`fs.watch` 递归 + 800ms 防抖、5 分钟全量轮、重试退避、索引持久化、回收区维护；`runCycle` 循环检查 `enabled` 支持中途取消；`notifyPeer` 停止联动通知。端口 `7892`。
- **配对码 pairKey**：6 位跨端关联码，主端自动生成、从端表单填写；请求统一注入，从端按 pairKey 匹配任务。
- **失败补偿**：失败文件保留旧 index 快照，下一轮 diff 自动重推。
- **停止联动**：主端停止 → `/api/sync/notify` 通知从端；从端停止 → 主端下轮收 409 → `peerStopped` 状态。

### 局域网设备访问记录与远程唤醒（P5）

- `core/access-log.js`：记录访问过本机服务的设备（拉取共享清单、群聊发言、文件同步请求时记录 requesterId+IP+来源+时间），只读展示；取代旧的 ARP 扫描方案。
- ~~`core/lan-devices.js`~~：已废弃，不再被 `main.js` 引用；保留文件仅作历史溯源。
- `core/wol.js`：MAC 归一化、魔术包构造（6×FF + MAC×16）、广播地址计算与 WOL 状态机。
- `electron/wol-service.js`：UDP 广播发包（每地址 3 次）→ 上线探测轮询（最长 30 秒）；目标存 `wol-targets.json`。

### 界面与测试

- `src/`：公共 React 界面；`App.jsx` 顶部页签含「设备中心 / 共享文件夹(Windows)或聚合挂载(Mac) / 群聊 / P2P传输 / 文件同步 / 运行日志 / 服务设置」。
  - `DeviceCenter.jsx`：设备中心，含「访问过本机的设备」区（取代原 ARP 扫描）与 WOL 配置。
  - `ShareManager.jsx` / `MountManager.jsx`：共享与挂载（含主机密码维护、密码遮罩、macOS 自动挂载 60s 轮询说明）。
  - `SyncPage.jsx`：文件同步多任务管理（任务卡片 + Modal 表单 + 配对码 + 失败补偿 + 停止联动 + 回收区）。
  - `TransferPage.jsx` / `ChatPage.jsx` / `LogPage.jsx` / `ServiceSettings.jsx`：传输（三块布局）、群聊（实名）、日志、端口与扫描设置。
- `test/`：公共、macOS 挂载、Windows ACL 与同步/WOL/访问日志/传输测试（27 个文件，123 项用例）。

## 维护规则

1. 后续只修改这个统一目录，不再把改动分别复制到旧的 Mac/Windows 目录。
2. 平台命令必须放在 `IS_WIN` / `IS_MAC` 分支，纯解析和格式化逻辑放进独立模块并写测试。
3. 提交前运行 `npm run check`；CI 在 Windows 和 macOS 两个平台执行同一套检查。
4. 用户配置保存在 Electron 的 `userData` 目录，不进入源码仓库。
5. `inner-net`、`inner-net-mac` 视为冻结的历史目录；任何新功能、修复、文档和发布都只进入 `InnerBridge`。
6. 群聊协议变更先修改协议/存储模块和测试，再接入桌面端与手机网页；避免两个客户端各自定义消息格式。远端 HTTP 只承载聊天，不暴露历史删除能力。

## 平台边界

- Windows 系统调用仅在 `IS_WIN` 分支执行，包括 `net`、`icacls` 和 PowerShell SMB cmdlet。
- macOS 系统调用仅在 `IS_MAC` 分支执行，包括 `/sbin/mount`、`diskutil` 和用户级 LaunchAgent。
- 两个平台都可以加载纯函数模块并运行全部测试，所以 Windows ACL 解析和 Mac 挂载脚本生成能在同一套 CI 中验证。
- 前端不复制页面入口：`App.jsx` 根据 `sys.platform` 选择 Windows 的 `ShareManager` 或 macOS 的 `MountManager`。
