# InnerBridge 0.2 系统使用说明

> 当前 0.2.0 功能（设备中心、安全配对、P2P 传输、文件同步、访问过本机设备记录、远程唤醒）已实现并通过 134 项自动化测试。完整的双端安装、功能和排障说明见[《项目使用指南》](项目使用指南.md)。

## 运行环境

- Windows 10/11 或 macOS
- Node.js `v24.19.0`（开发模式）
- 首次使用前在项目目录执行 `npm install`

## 顶部页签

应用启动后顶部包含：设备中心、共享文件夹（Windows）/ 聚合挂载（macOS）、群聊、P2P传输、文件夹同步、运行日志、服务设置。

## macOS 使用

双击 `启动 InnerBridge.command`，或执行 `npm run runtime:check`、`npm run dev`。在“聚合挂载”中导入 Windows 清单，选择手动或自动挂载；群聊页面填写 Windows 服务端地址。

### 主机统一密码（Mac 端）

- 在“聚合挂载”页进入「主机账号」维护区，对出现过的主机「设置/更新」SMB 统一密码，N 个共享只填一次；更新会覆盖该主机所有共享的密码。
- 共享级 `password` 留空也能挂载（自动用主机密码）；主端密码改了，在这里更新即可。
- 不再需要每条共享单独填密码；同步来的新共享为空也能挂。

### 使用 release 产物安装

- `InnerBridge-0.2.0-arm64.dmg`：双击打开，将“InnerBridge”拖入“应用程序”。
- `InnerBridge-0.2.0-arm64.zip`：解压后，将 `InnerBridge.app` 拖入“应用程序”。

DMG 与 ZIP 内容相同，任选其一即可。当前版本未配置 Apple Developer ID 签名，首次打开若被拦截，请右键应用选择“打开”，或在“系统设置 → 隐私与安全性”中点击“仍要打开”。该 ARM64 版本适用于 Apple Silicon（M 系列）Mac；Intel Mac 需重新构建 x64 版本。

## Windows 使用

建议右键以管理员身份运行 `启动 InnerBridge.bat`，或执行 `npm run runtime:check`、`npm run dev`。Windows 端负责 SMB 共享、共享清单接口和群聊服务；普通权限运行时高权限功能会受限。

“聚合挂载”目前仅在 macOS 端提供。Windows 端尚未实现聚合映射其他电脑共享的功能；如需从 Windows 访问 SMB 共享，请在资源管理器使用 `\\主机IP\共享名`，或通过 `net use` 映射网络驱动器。

### 共享密码遮罩

- 共享卡片的密码默认显示 `••••••••`，点击眼睛按钮可临时查看真实密码；「复制连接信息」始终复制真实密码，可直接在 Mac 端「导入清单」粘贴。

### 使用 release 产物安装

- `InnerBridge-Setup-0.2.0.exe`：右键选择“以管理员身份运行”，按向导安装。
- `win-unpacked/`：免安装目录，必须整体复制，运行其中的 `InnerBridge.exe`，不可只复制 exe 文件。

Windows 与 macOS 安装包不可混用，首次启动建议使用管理员权限。

## 设备中心与访问记录

- 设备中心列出已配对/发现的 InnerBridge 设备，支持发起配对、P2P 传输、设置远程唤醒。
- 「访问过本机的设备」区只读记录访问过本机服务的设备（拉取共享清单、群聊发言、文件同步请求时记录 requesterId+IP+来源+时间），**不主动扫描、不对任何设备发包**；仅显示与本机产生过实际交互的设备。
- 本机网卡 MAC 可复制，供对端配置远程唤醒使用。
- 远程唤醒（WOL）：为已配对且离线的设备「设置远程唤醒」（填目标有线网卡 MAC 与广播地址），再点「唤醒设备」发送魔术包；上线探测成功自动标记「已验证可唤醒」。

### WOL 实机验证与故障排查

「WOL 已配置」只表示目标 MAC 和广播地址已经保存在发送端，不代表目标设备已经具备被唤醒条件。首次配置后应进行一次真实的离线唤醒验证：

1. 确认填写的是目标设备的**物理有线网卡 MAC**，不要填写 Wi-Fi、蓝牙、虚拟网卡或扩展坞中不支持 WOL 的网卡 MAC。
2. 确认广播地址属于发送端与目标端所在网段。例如发送端为 `192.168.5.51/24`、目标端为 `192.168.5.50/24`，广播地址应为 `192.168.5.255`。
3. 先让目标设备进入睡眠，等待设备中心将其标记为「离线」，再点击设备卡片中的「唤醒设备」。睡眠验证通过后，再按需验证完全关机唤醒。
4. 点击后界面显示「唤醒中…」仅表示魔术包已经进入发送流程，应用还会轮询目标 InnerBridge 服务是否上线，最长等待 30 秒；应同时观察目标电脑是否自行恢复运行。

Windows 目标设备需要同时检查以下设置：

- BIOS/UEFI 中开启 `Wake on LAN`、`Resume by PCI-E` 或同类选项；如仍无法唤醒，检查并关闭可能切断待机网卡供电的 `ErP/EuP`。
- 「设备管理器 → 网络适配器 → 有线网卡 → 属性 → 电源管理」中勾选「允许此设备唤醒计算机」和「只允许魔术包唤醒计算机」。
- 网卡「高级」属性中启用 `Wake on Magic Packet`、`Shutdown Wake-On-Lan`、`Wake From Power Off State`（名称因驱动而异）。必要时临时关闭 `Energy Efficient Ethernet` / `Green Ethernet` 后复测。
- 睡眠后观察有线网口指示灯。如果网口灯完全熄灭，通常说明网卡在睡眠状态下已断电，需要优先修正 BIOS 或网卡电源管理设置。
- 使用管理员 PowerShell 执行以下命令，确认有线网卡具备并已获得唤醒权限：

```powershell
powercfg /devicequery wake_armed
powercfg /a
```

第一条结果中应包含目标有线网卡；第二条用于确认机器实际支持的睡眠状态。USB/Type-C 网卡、部分无线网卡和部分扩展坞可能不支持从睡眠或关机状态接收 WOL。

结果判读：

- 目标电脑没有任何启动反应：优先检查目标网卡 MAC、网口待机供电、Windows 网卡唤醒权限和 BIOS/UEFI 设置。
- 目标电脑已经启动，但界面仍提示「暂未上线」：WOL 本身可能已经成功，只是 Windows 或 InnerBridge 未在 30 秒内启动完成；此时不应按发包失败处理。
- 程序显示「已验证可唤醒」：表示发送后的探测窗口内目标 InnerBridge 服务曾上线。实机验收仍应以目标电脑确实由本次按钮操作自行唤醒为准，避免把人工唤醒误认为 WOL 成功。

## 文件同步

- 在「文件同步」页签以**任务**为单位管理：一次配置 = 一条同步任务，支持多条任务并存（各自目录、对端、忽略规则、启停状态独立）。
- 单向主从：主端目录变更推送到从端，主端是唯一事实来源。
- **配对码**：主端任务自动生成 6 位 pairKey，从端任务表单填写此码；两端靠它关联同一条同步（解决两端任务 id 各自独立导致 404 的问题）。
- **自动邀请从端**：主端新建任务并选择从端设备后，应用会立即发送经配对身份签名的同步邀请。从端收到后自动切换到文件同步页并弹出「接受主端同步邀请」窗口；任务名称、从端角色、配对码、主端设备、主端地址和端口均已填写且关键关联字段锁定，用户只需选择从端目录并创建任务。邀请未送达不会回滚已经创建的主端任务，主端会显示具体失败原因；对端上线后可在任务卡片点击「邀请从端」重新发送。
- 运行中的任务**不可修改配置/删除**（界面锁定 🔒），先「停止」再编辑；主端或从端停止任务都会通过签名通知即时告知另一端，并在对端当前界面弹出必须手动关闭的提示框，任务历史同时保留通知记录。
- 实时：`fs.watch` 监听 + 防抖；另有 5 分钟全量校验抗事件丢失。
- **失败补偿**：推送失败（重试耗尽）的文件下一轮自动重推（任务卡片显示「待补偿 N 个文件」）。
- 忽略规则：主端任务可配 gitignore 风格规则（`*` `?` 通配、`tmp/` 仅目录、`/` 开头锚定根），忽略项不推送也不触发从端回收；可「从目录选择」勾选文件/文件夹自动生成规则。
- 回收区：主端删除的文件在从端进入 `.innernet-trash/`，默认保留 7 天，可手动恢复或清空。
- 从端本地改动会在下一轮被主端覆盖或清进回收区；macOS 从端目录勿落在 SMB 挂载卷上。

## P2P 传输

- 页面采用类似 LocalSend 的侧边导航，左侧仅保留「接收 / 发送 / 设置」，右侧为当前功能的自由工作区。
- **发送**：分别选择文件或文件夹 → 从可信设备中选择在线已配对设备 → 发送；文件夹默认不压缩并保持目录结构，可在设置中切换为 ZIP；工作区展示选择结果和进度。
- **接收**：对端发起的传输提议集中出现在接收工作区，可接受或拒绝；接收目录在本机 Electron IPC 选择，远端不能指定；落盘前 SHA-256 校验后原子移动。
- **设置**：展示本机服务状态和监听地址，可切换文件夹是否压缩、手动修改缓存目录；缓存目录修改后重启应用完全生效。传输目标端口与对端需一致（默认 49152），Windows 防火墙需放行该端口入站。
- 挑战按配对留存公钥签发与校验；token（offer 时 Bearer）鉴权 chunk/status；无文件大小限制（流式分块）。

## 群聊与数据

支持文字、图片、普通文件、压缩文件和文件夹发送，文件夹会压缩为 ZIP。点击消息图片可进入大图预览，并可复制、下载或手动关闭；按 `Esc` 或点击预览空白区域也可退出。Windows“记录管理”可查看本机数据位置、清理缓存并导出 JSON/Markdown 历史。

## 跨端重要提示

- 对端解除配对时，无论本机当前停留在哪个页签，都会弹出「设备配对已解除」提示框。
- 对端停止文件同步任务时，会弹出包含任务名的停止提示框。
- 这两类提示不会自动消失，必须点击「我知道了」手动关闭，避免后台事件被遗漏。

## 服务设置

服务设置按当前项目的五项网络能力展示：设备发现、群聊/共享清单、安全配对、文件同步和原生传输。页面集中显示运行状态、协议、监听端口、功能说明与端口冲突建议；保存端口后重启应用统一生效。健康检查仅检测本机端口，不扫描局域网设备。

## 打包

macOS：`npm install` → `npm run check` → `npm run build:mac`；Windows：`npm install` → `npm run check` → `npm run build:win`。安装包输出到 `release/`。

`*.blockmap` 是更新辅助文件，请与对应安装包一起保留；`builder-*.yml`、`mac-arm64/` 和 `win-unpacked/` 属于构建辅助或免安装产物，普通用户只需安装包即可。

## 故障排查

先执行 `npm run runtime:check`；Electron 缺失执行 `npm run electron:ensure`。Windows 开发端口为 `6300`，聊天服务端口为 `7890`（共享清单接口同端口），配对服务 `7891`，文件夹同步 `7892`。拉取清单失败时检查 IP、设备中心的配对状态和 Windows 端服务是否在运行；挂载失败时检查 IP、SMB 账号口令、SMB ACL 和 macOS 隐私权限；文件夹同步失败检查对端 `7892` 是否可达且已配对。
