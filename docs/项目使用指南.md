# InnerBridge 0.2 项目使用指南

本文面向 InnerBridge 0.2 的最终用户和现场维护人员，介绍项目能力、Windows 与 macOS 的安装配置、跨端使用流程，以及常见问题的处理方法。

## 1. 项目简介

InnerBridge 是一套运行在同一局域网内的 Windows/macOS 协作工具。两端使用同一套程序，通过设备发现和 Ed25519 身份配对建立可信关系，提供以下能力：

- Windows 文件夹 SMB 共享与权限检查。
- macOS 多共享聚合挂载、统一主机密码和自动重挂。
- 局域网群聊、图片预览、附件发送、搜索和记录管理。
- 可信设备之间的 P2P 文件/文件夹传输。
- 多任务、单向主从的文件同步，支持忽略规则、失败补偿和回收区。
- 设备发现、安全配对、解除配对双端通知。
- 远程唤醒（WOL）配置、发送和上线验证。
- 运行日志、服务端口检测与配置。

InnerBridge 仅面向可信局域网使用，不提供公网中继或云端账号系统。

## 2. 平台职责

| 平台 | 主要职责 | 公共能力 |
| --- | --- | --- |
| Windows 10/11 x64 | 创建 SMB 共享、维护共享账号和 ACL、提供共享清单与群聊服务 | 设备发现、配对、群聊、P2P 传输、文件同步、WOL、日志与服务设置 |
| macOS Apple Silicon | 拉取 Windows 共享清单、保存本机 SMB 凭据、聚合挂载和自动重挂 | 设备发现、配对、群聊、P2P 传输、文件同步、WOL、日志与服务设置 |

当前“聚合挂载”是 macOS 客户端能力，底层调用 macOS 的 `mount -t smbfs` 和用户级 LaunchAgent。Windows 版可以正常创建、发布和管理 SMB 共享，但尚未实现把其他主机共享聚合映射成本机盘符；Windows 如需作为访问端，可先在资源管理器输入 `\\主机IP\共享名`，或使用 `net use` 映射网络驱动器。

## 3. 安装与首次启动

### 3.1 Windows

1. 运行 `InnerBridge-Setup-0.2.0.exe`。
2. 按安装向导完成安装，建议保留桌面快捷方式。
3. 首次启动或需要创建/修复 SMB 共享时，右键 InnerBridge，选择“以管理员身份运行”。
4. Windows 防火墙出现网络访问提示时，至少允许“专用网络”。

Windows 普通权限可以浏览页面和使用部分公共功能，但创建 SMB 共享、修复 ACL 等操作会被限制。

### 3.2 macOS

1. 打开 `InnerBridge-0.2.0-arm64.dmg`，将“InnerBridge”拖入“应用程序”；也可解压同名 ZIP 后拖入应用程序。
2. 当前构建未配置 Apple Developer ID 签名。首次打开若被 Gatekeeper 拦截，请在 Finder 中右键应用选择“打开”；仍被拦截时，进入“系统设置 → 隐私与安全性”，点击“仍要打开”。
3. macOS 端不需要管理员权限即可使用日常功能。启用自动挂载时，程序会安装当前用户的 LaunchAgent，不修改 SIP 保护的系统文件。

当前 macOS 发布包面向 Apple Silicon（M 系列）。Intel Mac 需要在 Intel 机器或对应构建环境中生成 x64 包。

### 3.3 首次检查

两台设备应满足：

- 连接同一局域网，且能够互相访问 IP。
- 系统时间基本一致。
- InnerBridge 均保持运行。
- 路由器/AP 未开启“客户端隔离”“访客网络隔离”等功能。

## 4. 推荐首次配置流程

1. 在两端打开“设备中心”，确认可以发现另一台设备。
2. 从任意一端发起配对，核对双方显示的六位配对码。
3. 在接收端确认允许配对。
4. 配对成功后，设备能力标签会按实际服务状态显示为可用。
5. Windows 创建 SMB 共享；macOS 拉取清单并配置该 Windows 主机的统一 SMB 密码。
6. 根据需要使用群聊、P2P 传输、文件同步或远程唤醒。

旧版本升级后若设备始终无法完成安全操作，建议双方解除配对后重新配对，以重新交换完整 Ed25519 公钥。

## 5. 功能使用说明

### 5.1 设备中心与安全配对

- 本机卡片展示设备 ID、运行能力及物理网卡信息。
- 其他设备只有在在线并完成配对后，才允许执行敏感操作。
- 一方解除配对时会通知另一方；对端当前界面弹出提示，必须手动关闭。
- “访问过本机的设备”只记录实际访问过本机服务的设备，不主动扫描局域网。

### 5.2 Windows 创建共享文件夹

1. 以管理员身份启动 InnerBridge。
2. 打开“共享文件夹”，选择“添加共享”。
3. 选择本机目录，填写共享名和 SMB 账号信息。
4. 保存后检查共享卡片状态；程序会校验共享对象和 `Full/Allow` 权限。
5. 密码默认遮罩显示；需要时可临时查看或复制连接信息。

Windows 本地账号必须设置非空密码，macOS 才能正常通过 SMB 认证。

### 5.3 macOS 聚合挂载

1. 先与 Windows 完成配对。
2. 打开“聚合挂载”，在主机账号区域为 Windows IP 设置统一 SMB 密码。
3. 点击“拉取共享清单”，或导入 Windows 端复制的共享清单。
4. 选择挂载方式：
   - 手动：立即调用 `mount_smbfs`，重启后需再次挂载。
   - 自动：安装当前用户 LaunchAgent，登录后守护并在网络恢复后自动重挂。
5. 所有共享默认挂载到聚合根目录下的独立子目录。

清单中的每个共享会依据 macOS 当前系统挂载表显示“已挂载”或“未挂载”；手动挂载/卸载后立即刷新，后台自动重挂时最多约 10 秒刷新。共享清单不会通过网络传输 SMB 密码；密码仅保存在 macOS 本机的加密凭据库中。

### 5.4 局域网群聊

- Windows 默认提供群聊服务，macOS 填写 Windows 地址，例如 `http://192.168.5.50:7890`。
- 支持文字、图片、普通文件、压缩文件和文件夹；普通附件和压缩包最大 200MB，文件夹选择后自动压缩为 ZIP。
- 点击聊天图片可预览、复制或下载。
- 支持搜索、回复、未读提示、系统通知和 `@昵称` 高亮。
- Windows 的“记录管理”可以导出 JSON/Markdown、删除消息、清理无引用附件或全部清空。
- 手机在同一局域网中可访问 `http://<Windows-IP>:7890/` 使用网页群聊。

群聊中的文件夹仍会在客户端压缩为 ZIP，受 500 个文件、原始和压缩后不超过 200MB 的限制；大文件夹建议使用 P2P 传输。

### 5.5 P2P 文件传输

1. 两端先完成配对并保持在线。
2. 发送端进入“P2P传输 → 发送”，选择文件或文件夹。
3. 从“可信设备”中选择接收端并发送。
4. 接收端进入“接收”，点击接受并选择保存目录；也可以拒绝。
5. 文件通过 SHA-256 校验后才会写入目标目录。

文件夹默认采用无压缩传输：程序内部使用无压缩容器保持目录结构，接收端校验后自动还原成文件夹。若更重视带宽，可在“P2P传输 → 设置”中开启“压缩文件夹”，此时发送 ZIP。

“设置”中还可修改传输缓存目录。缓存目录修改后需要重启 InnerBridge 才能完全切换接收服务；历史记录持久保存，界面默认展示最近五条，已完成或失败的记录可以删除。

### 5.6 文件同步

InnerBridge 文件同步是单向主从模型：主端是唯一事实来源，从端用于接收副本。

推荐流程：

1. 主端新建任务，选择主端目录和已配对从端设备。
2. 主端保存后自动向从端发送签名邀请。
3. 从端自动打开预填表单；确认任务信息，只选择从端目录并创建任务。
4. 双方启动对应任务。
5. 主端文件变更会实时推送；另有周期全量校验修复漏事件。

注意事项：

- 运行中的任务不可编辑或删除，需先停止。
- 任一端停止任务都会通知另一端并弹出手动关闭的提示。
- 主端删除的文件会进入从端 `.innernet-trash/`，默认保留 7 天。
- 主端可配置 gitignore 风格忽略规则，并决定被标记失效的忽略项是否在从端回收。
- 失败文件会保留为待补偿状态，下一轮自动重推。
- 不要把 macOS 从端目录放在 SMB 网络挂载卷上。

### 5.7 远程唤醒（WOL）

1. 从目标设备本机卡片复制物理有线网卡 MAC。
2. 在发送端为该可信设备配置 MAC 和广播地址，例如 `192.168.5.255`。
3. 让目标设备进入睡眠，等待设备显示离线。
4. 点击“唤醒设备”，应用发送魔术包并等待目标 InnerBridge 上线，最长约 30 秒。

“已配置”只代表参数已保存；只有真实唤醒并探测上线后才会标记为“已验证”。WOL 通常依赖有线网卡，Wi-Fi、USB 网卡和部分扩展坞可能不支持。

### 5.8 运行日志与服务设置

- “运行日志”显示应用启动、配对、共享、挂载、传输和同步过程，可暂停刷新或复制。
- “服务设置”可检测并修改服务端口；保存后重启应用生效。
- 端口冲突时页面会提示建议端口。

## 6. 默认端口

| 端口 | 协议 | 用途 |
| --- | --- | --- |
| 445 | TCP | Windows SMB 文件共享 |
| 7890 | TCP | 群聊、附件、共享清单 API |
| 7891 | TCP | 安全配对、传输挑战与撤销通知 |
| 7892 | TCP | 文件同步 |
| 49152 起 | TCP | P2P 文件传输，端口占用时自动尝试后续端口 |
| 49321 | UDP | 局域网设备发现 |
| 9 | UDP 广播 | WOL 魔术包常用目标端口 |

Windows 防火墙至少应允许 InnerBridge 在专用网络中访问这些端口。若修改端口，两端配置需要保持一致或通过发现信息正确识别。

## 7. 数据位置与备份

退出 InnerBridge 后再备份用户数据目录：

- Windows：`%APPDATA%\InnerBridge\`
- macOS：`~/Library/Application Support/InnerBridge/`

其中包含设备身份、配对凭据、共享/挂载配置、同步任务、聊天记录、WOL 目标和传输设置。不要在两台设备之间直接复制设备身份文件，否则可能造成设备 ID 或密钥冲突。

从旧名称“InnerNet 内网共享”首次升级到 InnerBridge 时，程序会复制旧用户数据并尝试重新加密迁移配对凭据和主机密码，旧目录会保留作为备份。若个别系统凭据无法迁移，重新配对并在“聚合挂载”中更新一次主机密码即可。

## 8. 常见问题与处理方法

### 8.1 找不到另一台设备

- 确认两端在同一子网且不是访客网络。
- 关闭路由器的 AP/客户端隔离。
- 检查 Windows 防火墙是否允许专用网络访问。
- 在“服务设置”确认设备发现和安全配对服务正常。
- 确认两端没有使用相同的复制用户数据目录。

### 8.2 配对成功但能力不可用

- 能力标签来自对端实时广播，服务未启动或旧客户端未广播该能力时不会点亮。
- 点击“重新发现”，确认对端 InnerBridge 保持运行。
- 老版本配对记录可能只有指纹、没有完整公钥；双方解除配对后重新配对。
- 检查对应端口是否被防火墙拦截或被其他程序占用。

### 8.3 macOS 挂载失败或提示权限不足

- 确认 Windows IP 可达且 TCP 445 已放行。
- 确认 Windows 本地账号有密码，并已获得共享级 `Full/Allow` 权限。
- 在 macOS“聚合挂载 → 主机账号”更新正确密码。
- Windows 密码更改后，macOS 保存的旧密码不会自动更新。
- 路径含中文或空格无需手工编码，应交给 InnerBridge 处理。

### 8.4 Windows 无法创建共享

- 退出后右键 InnerBridge，选择“以管理员身份运行”。
- 检查目标目录确实存在，且未被安全软件的文件保护功能拦截。
- 使用 PowerShell 执行 `Get-SmbShareAccess -Name "共享名"` 检查账号、`Full` 和 `Allow`。
- 若同名旧共享已存在，先在 InnerBridge 中确认其目录和账号，不要直接删除实际文件夹。

### 8.5 群聊连接失败

- macOS 地址应包含协议和端口，例如 `http://192.168.5.50:7890`。
- 确认 Windows 群聊服务正在运行且 7890 入站可达。
- 昵称默认使用设备名；消息必须携带本机设备身份，匿名或旧网页请求会被拒绝。

### 8.6 P2P 一直等待或发送失败

- 确认设备在线且已配对，能力标签“发送文件/接收文件”可用。
- 接收端必须手动点击接受并选择目录，发送端才开始传输。
- 检查 P2P 端口（默认 49152）和配对端口 7891。
- 缓存目录必须可写，并留有大于待传输内容的可用空间。
- 文件夹开启压缩时会先生成 ZIP；大文件夹在发送开始前可能需要等待。

### 8.7 文件同步没有更新

- 确认两端任务都已启动，角色分别为主端和从端。
- 检查配对码、对端设备、IP 和 7892 端口。
- 查看任务卡片是否显示“对端已停止”或“待补偿”。
- 使用“立即同步”触发一次检查；必要时停止任务后清空索引再启动。
- 检查忽略规则是否误排除了目标文件。

### 8.8 睡眠后无法 WOL 唤醒

- 必须填写目标设备物理有线网卡 MAC，不要使用 Wi-Fi、蓝牙或虚拟网卡。
- BIOS/UEFI 开启 `Wake on LAN`、`Resume by PCI-E` 等选项，并检查 `ErP/EuP` 是否切断待机供电。
- Windows 网卡“电源管理”勾选“允许此设备唤醒计算机”和“只允许魔术包唤醒计算机”。
- 网卡高级属性开启 `Wake on Magic Packet`、`Shutdown Wake-On-Lan` 等选项。
- 睡眠后若网口指示灯完全熄灭，优先处理 BIOS 或网卡待机供电。
- 管理员 PowerShell 可执行 `powercfg /devicequery wake_armed` 和 `powercfg /a` 检查支持情况。

### 8.9 macOS 提示应用损坏或无法验证开发者

确认安装包来自可信构建后，在 Finder 中右键应用选择“打开”；或到“系统设置 → 隐私与安全性”允许打开。不要从不可信来源执行绕过 Gatekeeper 的命令。

### 8.10 端口被占用

进入“服务设置”点击“重新检测”，按建议端口修改并保存，然后重启两端应用。P2P 传输端口会在默认端口占用时尝试后续端口，但防火墙仍需允许实际监听端口。

## 9. 开发与源码运行

开发环境要求 Node.js `v24.19.0`、npm `11.17.0`：

```bash
npm install
npm run runtime:check
npm run dev
```

完整检查和平台打包：

```bash
npm run check
npm run build:mac
npm run build:win
```

安装包输出到 `release/`。本次 macOS Apple Silicon 的 DMG/ZIP 已在 macOS 生成并完成完整性检查；Windows 安装包由 Windows 环境执行 `npm run build:win` 生成。macOS DMG/ZIP 必须在 macOS 构建。
